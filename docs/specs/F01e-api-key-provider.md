# F01e — OpenAI-compatible API provider and explicit excerpt consent
Base: F01d. Implementation branch: feat/f01e-api-provider. Separate PR from F01f.

Scope: user-configured HTTPS public-looking /v1 endpoint and model, API key, connectivity probe, bounded response/timeout/cancellation and clear errors. Browser preview only keeps the API key in memory and uses provider CORS; reload forgets it. Desktop WebView (when Tauri global bridge is present) sends the key once to native command, which saves it in the **OS credential store** via keyring and performs inference in Rust; never serializes the stored secret into IndexedDB, exported preferences, log output or frontend. Desktop keyring availability is OS-dependent; failure must be visible, not silently downgrade to plaintext.

No default provider, silent remote network on startup, Folio proxy, or document upload. Connection probe is an explicit minimal billable model request, not silent ping. Excerpt translation remains behind F01d per-request confirmation and shows only text explicitly selected/pasted; do not assume API/CLI subscription equivalence. Endpoint validation rejects HTTP, local/IP literal targets, URL credentials, query, fragment and redirects. Public-looking HTTPS validation is **not** a full SSRF/DNS rebinding guarantee; desktop native HTTP transport should harden redirects, response cap and timeout. Do not claim arbitrary compatible providers are tested or that browser CORS always permits them.

Acceptance: provider identity/model distinct cache keys; bad URL/key/model rejected; HTTP 401/429/server, timeout, abort, malformed/oversized response and missing content surfaced without key exposure. Existing manual/offline workflow remains functional. 100% TypeScript coverage across new modules, Rust check/tests, production build and independent review/manual network+keychain smoke gate before merge. Rollback: no document schema migration, desktop stored key deletion command.
