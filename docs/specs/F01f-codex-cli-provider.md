# F01f — first authenticated local Agent CLI adapter (Codex)

Stacked PR onto F01e until F01e merges master. Scope: desktop-native Codex CLI only. No generic arbitrary command, no silent install/login, no reading/copying CLI tokens, no shell interpolation. Browser shows CLI unavailable with actionable explanation. Codex login status may be checked explicitly; status does not guarantee account allowance, API usage rights, model availability or successful inference.

Codex adapter uses documented `codex --version`, `codex login status` (zero exit = logged in), `codex exec --json --sandbox read-only --ignore-user-config --skip-git-repo-check --ephemeral --model <explicit-model> -` with prompt via stdin, never argv. Native process starts in a newly created empty temporary workspace; original document and library files are not mounted/copied. No shell, dynamically selected command/flags, writable sandbox or yolo. CLI may still contact its remote model provider using existing authenticated user credentials; tell user before sending an excerpt. User's local CLI access is not equal to a right to repackage its backend API. Do not return CLI auth output, stderr or raw JSONL to UI.

Limit stdout to 256 KiB and final text to 16 KiB, stderr to null; 90s process timeout; kill on drop and user-initiated cancellation; exact request-id match and bounded source text. Parse only `item.completed` with `agent_message` as plain text and reject `turn.failed` or nonzero process exit. Rust unit tests for safe fixed argv, malformed/incomplete JSON, invalid model/request, no payload leakage. Runtime smoke on installed/authenticated macOS/Windows/Linux Codex required before declaring desktop integration generally available. Tests use mock bridge, never user credentials.

Use F01d provider-neutral identity (ID `cli:codex`, selected explicit model). Switching from API or manual leaves local cache untouched and changes identity. Only active after user checks status and chooses model; no implicit CLI startup on opening a document. User confirms per excerpt through F01d. Browser and Tauri modes are mutually explicit; no browser "mock logged in" view.

Risks: read-only sandbox and ignore-user-config reduce risks but OS process isolation and runtime auth depend on the installed Codex version; the process can read its authentication environment and contact remote inference. Validate installed CLI flags/terms before release, never claim absolute sandbox. Rollback: revert stacked PR, no database/schema migration and no modifications to Codex login state.
